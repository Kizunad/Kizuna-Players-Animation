# mine_main：主手镐 / 斧 / 锹连续挖掘（默认每 5 tick 一次下砸）

> 2026-10-23 用户修订：加大举镐与砸下的姿态差，胸腰先带动肩，再伸肘、压腕；击中后短暂停住再回举，保持 0–0.20 秒循环接缝。潜行时使用独立支撑底层，不覆盖双腿。以下数值表为前版记录，当前值以 `.bbmodel` 为准；副手同步镜像，效果待审图与游戏内验收。

> 审阅状态：待审阅（2026-10-22，第三批）。轴向、坐标和数值来源见 [共用约定](conventions.md)；驱动方式与已通过的 [attack_main](attack_main.md) 相同。
> 数值已用设计期原型轨道做过正向运动学、三视角预览和门禁同算法检查（`scripts/analyze_animation.py` 当前版本）。

## 1. 动作目的与触发

- **用途**：手持挖掘工具（`MiningToolItem`：镐、斧、锹、锄）挥动时的挖掘/砍树动作。视觉速度为原来的 0.8 倍，默认连续下砸周期由 4 tick 延长到 5 tick；原版挖掘声、裂纹和破坏判定不改。
- **触发与驱动**：`VanillaAnimationScheduler.scheduleHandSwing` 选 `mine_main/off`，独立游标每 tick 增加 `0.60 × 0.8 / getHandSwingDuration()` 的归一化进度。原版挥手进度回绕只标记续播请求，不立即重置视觉游标。
- **连续挖掘**：**0–0.20 s 是一个完整循环，0.20 s 与 0 s 同姿态**。有续播请求时在视觉游标走完循环后回绕；客户端跨接缝正向插值，不倒放经过砸击段，也不重建淡入。
- **单次挥动与松手**：没有再次挥手时不回绕，从当前游标继续播放到 0.50 s；收势使用同一 0.8 倍速度，不跳到固定尾段，单次点击不会多砸一次。
- **急迫 / 挖掘疲劳**：沿原版挥手时长缩放视觉速率，循环始终完整覆盖 0–0.20 s。

## 2. 时间轴

剪辑长度 **0.50 s**（10 tick），`loop: false`。

| 段 | 时间 | 内容 |
| --- | --- | --- |
| 接缝 / 举顶 | 0.00–0.03 | 镐举在右肩上方、头右外侧，胸后仰到 +1°（下砸前的蓄力），胯后坐 1.4 px，双膝屈约 29° |
| 下砸 | 0.03–0.11 | 胯先下沉后坐（0.075 s 到底），腰、胸前屈，肩、肘、腕依次下砸；**0.11 s 镐尖击中**，手腕 0.125 s 到位 |
| 回弹 / 回举 | 0.11–0.20 | 手腕再压 2°（0.145 s）后，肩肘把镐举回到顶点的 90%；0.20 s 回到 0 s 的姿态 |
| 连续挖掘回绕 | 0.20 → 0.00 | 默认每 5 tick 走完视觉循环，原版续播请求不截断动作 |
| 放下（单次挥动） | 0.20–0.50 | 镐沿肩前放回身侧持物姿态，膝伸直、胯回中，头抬回平视 |

时间线：无事件（挖掘声与裂纹由原版自身处理，不额外发 `hit`）。

## 3. 分阶段全身姿势

右臂按“肩 → 肘 → 腕”依次晚约 0.01 s；躯干先于手臂：胯 0.075 s 到底、腰 0.075 s、胸 0.09 s，肩 0.11 s，肘 0.115 s，腕 0.125 s。腿由胯的姿态做脚底锁定求得，双脚全程全掌着地。

- **举顶（0.03 s）**：右上臂前举 76°、水平外展 10°、外展 35°，肘屈 55°，手腕桡偏 12°：镐柄斜向后上，镐头在头顶右后方。头始终低 13° 盯着方块；左手屈肘 56° 护在身前（上臂前举 12°、外展 13°），左手半握。
  胸后仰到 +1°、右转 2.5°，腰 −1°、右转 3°，把右肩向后带出蓄力；胯后坐 1.4 px、下沉 0.45 px、前倾 2.5°、右转 2°。
- **下砸（0.06 s 中途 / 0.11 s 击中）**：胯先下沉到 −0.9 px、后坐到 2.2 px、前倾 4.5°、左转 1.5°，腰前屈 7°、左转 2°，胸前屈 9°；
  右上臂从 76° 砸到 52°，同时内收（水平外展 10° → −13°）、外展 35° → 12°，手从头右外侧划到胸前正中偏右；肘伸到 32°；手腕尺偏到 −14°，镐头最后甩下。头抬 3°（−13° → −10°）并跟着右转 2°，视线保持在方块上。
  左上臂前举 21°、肘屈 63°，左手略往回收，给右臂让出空间。
- **回弹（0.145 s）**：手腕再尺偏 2° 后停住（镐尖“咬”进方块），胯继续下沉到 −0.95 px，腰胸到最前（−7.5° / −9.5°）。
- **回举（0.20 s）**：胯回到 1.4 px 后坐、膝回到 29°；右上臂回到 73.6° / 7.7° / −32.7°，肘 48°，腕回到 2°；与 0 s 同姿态。
- **放下（0.30 / 0.40 / 0.50 s）**：右上臂 60° → 32° → 15°，肘 40° → 10°，腕回 3°；胸腰回零，头 0.25 s 后才开始抬回（−12° → −5° → 0°），膝伸直。末帧即持物站姿，与 attack_main 起止姿态只差右前臂 2°（10° 对 12°，为满足“恢复”判定留出余量）。

## 5. 运动链错峰

下砸方向（肩、肘前屈减小，腕尺偏）的有符号角速度峰值，60 Hz：

| 骨 | 胯 | 腰 | 胸 | 右上臂 | 右前臂 | 右手 |
| --- | --- | --- | --- | --- | --- | --- |
| 峰值时刻 (s) | 0.04 | 0.050 | 0.067 | 0.067 | 0.083 | 0.100 |

胯先坐下，腰、胸前屈带动肩，肘、腕依次甩出；腕峰值 442°/s 是全段最快。回举（0.11–0.20 s）比下砸慢：右上臂回举 24° 用 0.12 s，下砸 24° 用 0.08 s，所以门禁取到的主动作峰值都落在下砸段。

## 8. 索引条目与叠加

`mask: full`、`priority: 20`、`blend_in: 0.04`、`blend_out: 0.14`、`hand: main`、`fpv: false`；不声明 `impact_window`（严格上限内已满足）。
底层是 walk / run / sneak / jump_air / ride 时只取 `upper`（运行时动态遮罩，同 attack）。动作目录时长 10 tick（现为 13，需同步）。

## 9. 与其他状态的衔接

- 进入：`stand`、`walk`、`run`、`sneak`、`jump_air`、`ride`；`swim`、`climb`、`sleep`、`elytra` 中不播放（见 [transitions](transitions.md)）。
- 连续挖掘：同一 ID 重复 scrub，0.15 s → 0.20 s ≡ 0 s 回绕（见第 11 条对运行时的要求）。
- 挖掘中换成剑或空手挥动：调度换成 `attack_main`，旧实例从当前姿态淡出 0.14 s。
- 结束：挥动停止后收势 0.20 s 播到 0.50 s 再淡回底层。

## 11. 待审事项

- 连续挖掘依赖运行时把“进度从高位回到 0”当成回绕，而不是现在的 0.05 s 权重淡入：现行 `scrubRestartAt` 会让动作权重在每次重开时掉到 0 再升回，挖掘时手臂每 0.20 s 闪回底层一次。另外 scrub 游标只在服务端 tick 更新，0.20 s 的循环只取到 4 个姿态。要求已写入「分工」。
- 下砸力度受一次性动作 1.5×10⁶°/s³ 的角加加速度上限约束，现为“利落但不重”的砸法。若审阅方希望更重的砸击，可把 `mine_main` / `mine_off` 也加入打击窗白名单（0–0.20 s），下砸幅度可加大到肩 40° 左右。
