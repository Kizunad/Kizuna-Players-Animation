# head_follow：扭头带动身体（视线叠加层）

> 状态：设计稿与加性视线层接口已审阅通过；2026-10-26 已录入 classic `.bbmodel`、导出两段资源（索引 `layer: look`），
> `PlayerMeshRenderer` 已接入并有 `LookLayerTest` 回归。分配曲线：小角度主要由脖子承担，胸 `12·u^1.3`、腰 `8·u^1.6`（u = |Δ|/50）；
> 俯仰胸 `16·v^1.4`、腰 `12·v^1.8`（v = |Δ|/90），头取余量。游戏内视觉验收尚未执行。

## 1. 动作目的与触发

- **用途**：原版把视线偏航全部放在脖子上：`head.yaw = netHeadYaw`；身体偏航 `bodyYaw` 在 `LivingEntity.turnHead`
  中每 tick 追随 30%，并保证 `|headYaw − bodyYaw| ≤ 50°`。所以头可以相对身体转 ±50°、俯仰 ±90°，躯干完全不动。
  本动作把相对偏航按比例分给胸、腰，俯仰分给胸腰，形成“转头带肩、低头带胸”的联动。
- **现状问题**：所有已交付资源（包括 `walk` / `run`）都有 `head` 旋转轨道，覆盖式混合会丢掉原版视线；目前只有望远镜、号角、
  持弩在 `applyArmPosePitch` 里把俯仰补回头部。新增的长时间动作（吃喝、拉弓、格挡、潜行、骑乘等）都需要视线。
- **触发**：客户端每帧，被渲染玩家处于站立类状态（站、走、跑、潜行、骑乘、攀爬、打坐及其上层动作）时启用；
  睡眠、泳姿、鞘翅（只叠偏航）、激流、死亡时关闭。
- **原版进度来源**：`netHeadYaw = headYaw − bodyYaw`（插值后，度，±50）与 `headPitch`（度，±90）。

## 2. 资源与时间轴（姿势空间剪辑）

两段剪辑，**时间轴表示角度而不是时间**，由运行时按角度取样后**加到**已混合的姿态上（加性），不参与优先级覆盖：

| 资源 | 长度 | 时间 → 角度 | 零姿态 |
| --- | --- | --- | --- |
| `head_follow` | 1.0 s | `t = (Δyaw + 50) / 100`，Δyaw ∈ [−50°, 50°]（面板正方向 = 向右转头） | t = 0.5 全零 |
| `head_follow_pitch` | 1.0 s | `t = (Δpitch + 90) / 180`，Δpitch ∈ [−90°（抬头）, 90°（低头）] | t = 0.5 全零 |

两段都 `loop: false`，关键帧在 0、0.1、…、1.0（每 10° / 18° 一帧），保证角度到姿势单调平滑、t = 0.5 两侧速度连续。

## 3. 分配（右转 50° 时，左转为镜像：Y、Z 取反，左右臂交换）

| 骨 | Δyaw = +25° | Δyaw = +50° | 说明 |
| --- | --- | --- | --- |
| head | Y +16, Z +1 | Y +30, Z +2 | 脖子承担 60%，转到极限时略歪头 |
| chest | Y +6, Z −0.5 | Y +12, Z −1 | 胸承担 24%，晚于头（加性层无时间，峰值次序不适用） |
| waist | Y +3 | Y +8 | 腰承担 16%；胯不转，双脚不扭（叠加在 `walk` 上时脚不会滑） |
| r_upper_arm | Y −2, X −1 | Y −4, X −3 | 右肩后撤时右臂稍后摆 |
| l_upper_arm | Y −2, X +1.5 | Y −4, X +4 | 左肩前送时左臂稍前摆，避免手臂跟胸“焊死” |
| r_forearm / l_forearm | +1 / +2 | +2 / +4 | 肘随摆臂微屈 |

| 骨 | Δpitch = −90°（抬头看天） | Δpitch = +45° | Δpitch = +90°（低头看脚） |
| --- | --- | --- | --- |
| head | X +62 | X −34 | X −62 |
| chest | X +16 | X −7 | X −16 |
| waist | X +12 | X −4 | X −12 |
| r_upper_arm / l_upper_arm | X −4 | X +3 | X +6（低头时肩前扣） |

颈部最大 62°（< 75°），胸 16°、腰 12° 都在上限内。头 + 胸 + 腰合计等于原版角度，因此视线方向与原版一致。

## 4. 运行时规则（接口提议）

1. `PlayerMeshRenderer.frame`：原版底层姿态中**去掉**头部的视线偏航/俯仰（仍保留潜行时的头部位移），再按常规混合各资源；
   之后若启用视线层，按第 2 节公式取样两段剪辑，把每根骨的旋转分量直接相加（位移不加）。这样无论上层资源有没有头部轨道，
   视线都只被计算一次。
2. 与已有俯仰补偿的关系：`spyglass`、`toot_horn`、`crossbow_hold` 现在在 `applyArmPosePitch` 里给头加俯仰；启用视线层后
   这些动作的头部俯仰改由视线层提供，`applyArmPosePitch` 只保留手臂部分，避免加两次。
3. 例外权重：`drink` 末段已仰头 22°，俯仰层按 50% 权重；`eat` / `drink` 的低头/仰头属于动作本身，偏航层全权重。
   鞘翅只叠偏航；打坐可叠偏航与俯仰（吐纳允许转头）。
4. 资源仍按普通动画录入 `.bbmodel`、导出 JSON、写进索引（`mask: upper`、`hand: none`、`priority: 0`），但**不经过**
   `AnimationPlayer` 的播放/同步；服务端不发送请求。索引字段 `"layer": "look"` 标明加性视线层（已写入契约），运行时按固定 ID 取两段并检查该字段。

## 5. 重心与支撑

不改胯和腿，叠加后重心变化 < 0.1 px，不影响底层动作的着地。

## 6. 门禁（需审阅确认判据）

姿势空间资源没有“预备/跟随”“错峰”“角速度”的时间意义。提议对 `layer: look` 资源单独检查：

- 关节角度上限（同上）；
- 单调性：Δ 从 −50→50 / −90→90 时每根骨主轴角度单调；
- 对称性：`pose(−Δyaw)` 等于 `pose(+Δyaw)` 的左右镜像（误差 ≤ 0.05°）；
- 组合采样：叠加在 `walk`、`sneak`、`eat` 上按 ±50° / ±90° 采样，手臂穿模与脚底门禁仍通过；
- 有效骨骼数按“Δ 走满全程”计：head、chest、waist、双上臂、双前臂共 7 根，**少于 10 根**——这是视线层的固有性质，请审阅方确认
  该资源按姿势层判据验收，而非一次性动作的 10 根要求。

## 7. 规模预估

两段各 7 骨、11 帧 × 7 ≈ 77 关键帧，合计约 150。
