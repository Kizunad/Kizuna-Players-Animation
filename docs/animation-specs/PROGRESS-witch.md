## 共用约束

**W1 起止与收势。**
- 首帧、末帧都等于 `stance_idle` 首帧，速度为零；手指取 `stance_idle` 导出资源 0 s 的值（右拇指 `(10, 0, 47.15)`、两组 76.44° / 82.76°，左 `(8, 0, −45.57)`、−75.17° / −81.65°），不取第 3 节的设计值（五脏诀握持覆盖层的教训：导出 0 s 随呼吸松了约 3°）。
- 收势从效果时刻（`cast`、`release`；熬药 31.00）起；**收势前半段内双脚回到架势踝位**。两脚锁定的式（除熬药、掷引外都是）在前半段内把胯位置、旋转和重心回到架势（待决定第 17 条）。
- 不动 `root`。首尾两端逐帧出关键帧（五脏诀制作实测：均匀 Catmull-Rom 在疏密不匀的键之间会抬高短段末端的速度）。

**W2 手型。** 照动作稿 §2.2 的右手面板值，左手 Z 取负；掌、捧掌、剑指同五脏诀 E3：

| 手型 | 用在 | 拇指 (X, Y, Z) | `fingers_a` Z | `fingers_b` Z |
| --- | --- | --- | --- | --- |
| 握瓶 / 握棍 | 主手，全程 | 同架势拳 | 同架势拳 | 同架势拳 |
| 捏塞 | 左手拔塞 | (25, 0, 40) | 45 | 85 |
| 托掌 | 左手接药 | (20, 0, 15) | 25 | 30 |
| 扇 | 左手（熬药） | (5, 0, 0) | 0 | 0 |
| 松手 | 主手，掷引出手后 | (20, 0, 15) | 15 | 20 |
| 剑指 | 左手捏诀（噀催） | (10, 0, 60) | 0 | 90 |

- 换手型时三片手指错开 1–2 帧，不同步。

**W3 拔塞。** 服药 0.00–0.50（`cork` 0.30）、敷药 0.00–0.40（0.25）、泼引和噀催 0.00–0.30（0.15）：
- 右拳把瓶提到胸前、瓶口朝上；左手成捏塞到瓶口，拔（向上约 1.5 px，最快的一下），往左外甩开约 3 px，再去下一段的位置（服药按胸、敷药托掌、泼引噀催回护身位握拳）；
- 拔、甩是左腕和左前臂的快动作，≤ 720°/s；掷引不拔塞，先摇瓶。

**W4 瓶口到嘴**（服药三口、噀催含药）：
- 瓶不在骨架里，门禁查不到。原型按「握瓶手型下瓶口在拳前上方约 4 px」估算（动作稿 §5），瓶口离嘴约 1 px；嘴在架势下约 `(−0.4, 22.9, −5.9)`（探针 P5），随头的姿态走；
- 右拳、右前臂对头 ≥ 0.25 px；腕翻 ≤ 120°；送瓶姿势参照 [drink](drink.md)；
- 像不像在喝，由用户看 GIF 判断。

**W5 相触与穿模。**
- 贴身段用 `hand_contact_windows`（五脏诀 E9 的规则）：窗口里每一帧至少一对「手 ↔ 目标」间隙 ≤ 0.5 px，所有对的穿入 ≤ 0.25 px；手指算在手里；目标是另一只手（含手指）、另一条前臂、头、胸、腰、胯、两条大腿；窗口不比真实接触宽。
- 粗、细两套几何一起约束，贴身滑动逐帧求解（五脏诀制作实测：细臂手厚 3 px、枢轴往里往下各 0.5 px，两手间隙两套差 0.5–0.8 px）。
- 三段要用：服药（左掌按胸、抚腹）、敷两臂（左掌抹右前臂、右腕蹭左前臂）、敷两腿（两手搓大腿、拍腿）。改了设计以后都落在现有目标里，不用加「头、颈」目标（动作稿 §7；头颈那段先不做）。
- **穿模自查**（不入门禁）：前臂、手对头的穿入 ≤ 架势基线（约 1.0 px）；手臂和身体之间原本就有 1.0–1.5 px 的固有交叠，不算新问题。

**W6 预备 / 跟随与错峰。**
- 一次性动作的预备门禁按 `腰 → 胸 → 右上臂 → 右前臂 → 右手`（`_off` 取左），每根动着的骨最快的那一下前要有 ≥ 3° 的反向、后要有 ≥ 3° 的过冲再回位，60% 以上的骨通过才过（五脏诀常常正好 3/5）。保持剪辑末段收敛即过。
- 每段第一个动作如果就是全段最快，前面没有反向：进式、拔塞要比后面的主体慢，或者给它补一个反向（各页第 3 节写了）。
- 错峰按 `phases` 查右臂链，主链里动的不到 3 节的阶段跳过；没声明 `phases` 时按整段查。动作稿要的左臂链见待决定第 7 条。

**W7 着地与滑脚。**
- 架势后脚提踵。除熬药（开立、收步各落一次）和掷引（后脚离地再落回一次）外，两脚整段锁定，后脚不落平：提踵落平踝降 0.72 px，一次着地就超滑脚门禁 0.5 px（五脏诀 E7）。
- 每帧最低点 ≥ −0.20 px（着地门禁 0.25 px，留 0.05 px 余量），俯身的敷两腿最紧（−0.18 px）。

**W8 视线层。** `head_follow` 照常叠加（五脏诀 E8 的分摊）；主剪辑里头的偏航 ≤ 45°（掷引后引 −44° 到顶），叠上视线层不超过颈的 75°。瓶口到嘴时的俯仰见待决定第 15 条。

**W9 握持与覆盖层。**
- 主手：七段全程握着（掷引 1.00 以后松手），加入 `GRIP_IDS` 只查右手；不叠主手握持覆盖层。
- 副手：服药、熬药、掷引、泼引、噀催在副手有东西时叠 `evoker_grip_off`（动作稿 §2.2）；拔塞、按胸、扇、剑指都握着东西做，是已知的小问题。敷药要求副手空着（行药诀 §4.1），不叠。
- 下料覆盖层和僵直的手指保持架势握拳常数，不另叠。

**W10 开立（只有熬药）。** 照五脏诀 E2，按制作实测改：预压胯 `(0.75, −1.7, 0.4)`，右脚 0.20 离地（0.25 离地时右小腿约 750°/s），摆动中胯 `(0.75, −0.4, −2.0)`，0.50 全掌落 `(−3.7, 1.0, −2.6)`；左脚碾正只转约 1.5°；开立胯 `(−0.7, −0.10, −2.4)`、膝约 10°（膝角对胯高很敏感：y −0.16 约 15°）。收步反过来，以提踵落回 `(−1.7, 1.72, 3.2)`。

**W11 速度与爆发。** 一次性动作各骨 ≤ 720°/s；爆发窗口最长 0.08 s。动作稿给的三段爆发窗口都是 0.15 s，声明不了，按普通上限做（待决定第 8 条）：掷引肘伸峰值目标 ≤ 650°/s，泼引甩腕 ≤ 700°/s，掷引松手 ≤ 720°/s。

**W12 按倍率播放。** 资源按倍率 1 制作，门禁按倍率 1 跑；运行时按倍率 r ∈ (0, 1] 放慢整段：剪辑时间和事件时刻 ÷ r，淡入淡出仍按真实秒。每段另出一份 × 0.8 的 GIF 看节奏；放慢只会让角速度和抽搐变小，不会让门禁变差。实现见待决定第 3 条。

**W13 门禁集合与索引。**
- `FULL_BODY_IDS` 加七段主剪辑和 `status_stagger`；`GRIP_IDS` 加七段主剪辑；`ARM_OVERLAY_IDS` 加 `"witch_brew_feed_off": "l"`。
- `BURST_WINDOW_PREFIXES`、`UNBALANCED_WINDOW_PREFIXES` 先不加，实测超了再说（待决定第 8 条）。
- `hand_contact_windows` 只有服药、敷两臂、敷两腿；`phases` 见各页第 7 节。
- 对称或成对的两臂动作，左臂比右臂晚 1–2 帧、幅度不同，避开曲线相关性门禁。

3. **按倍率播放（新能力，所有功法书通用）。** 动作稿 §3、§7 要「`play` 多一个倍率，剪辑和事件按倍率拉长，起点同步、观察者补发都带上」。PA 26.2 待办清单（`pa-26.2-backlog.md`）里没有这一项；现状是 `AnimationPlayer.Playback` 用 `now − start` 直接当剪辑时间。
   **建议**（最小改动，约 0.5 d，排在 B1 之后，因为行矢的 `AimWindow` / `ItemStates` 也改 `AnimationPlayer`）：
   - **语义**：倍率 r 只收有限值 (0, 1]（迟滞只会放慢）；剪辑时间 = 真实经过秒 × r，事件在剪辑时刻 ÷ r 的真实时刻触发；一次性动作在 `start + 时长 ÷ r` 开始淡出；淡入淡出仍按真实秒；资源和门禁不变。r = 1 时行为与现在逐位相同。
   - **协议**：`PlayRequest` 加 `optional float playback_rate = 6`（下一个空号）；缺省为 1；`validate` 拒绝 0、负数、NaN、无穷和 > 1；与 `normalized_progress`（按进度拖动）同时出现时拒绝，不静默忽略。实体的 `Play` 先不加（第 18 条）。
   - **服务端** `ServerPlayerAnimations`：加 `play(player, action, rate)`、`playFrom(player, animation, startTick, rate)`；旧重载按 r = 1 委托，**不写这个字段**（旧调用的线上字节不变）；到期 tick 改成 `startTick + ceil(naturalDurationTicks ÷ r)`；`AnimationSyncState` 存整条 `PlayRequest`，晚到的观察者补发自然带上倍率；`/kpa_server play` 加可选倍率参数供人工验证。
   - **客户端**：`ClientAnimationNetworking` 读出倍率（缺省 1）传给 `PlayerPlayback.play`；`AnimationPlayer.PlaybackRequest` 加 `double rate`，`AutomaticAnimationPlayer`、按进度拖动、`EntityAnimationApi` 都传 1；`restartEquip` 的已过时间 × r。
   - **`AnimationPlayer.Playback`** 四处：`time()`、`eventEnd()` 的 elapsed × r；`fadeStart()` 的自然结束 `start + duration ÷ r`；`play` 里补发事件的 `lastEventTime = (now − start) × r`。`weight()` 的淡入按真实秒不动；`normalizedProgress()` 走 `time()`，自然跟上。
   - **测试**：`AnimationTest` 加 r = 0.8（真实 1.0 s 时剪辑在 0.8 s；剪辑 0.8 s 的事件在真实 1.0 s 触发；淡出从时长 ÷ 0.8 开始）；`ProtocolContractTest` 加拒绝 0、NaN、> 1 和与进度同时出现；服务端到期与补发带倍率各一条。
